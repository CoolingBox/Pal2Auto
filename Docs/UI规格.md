# Pal2Auto UI 规格

> 适用：960×540 逻辑画布（`SubViewport`，按内部渲染倍率出图）→ 原样贴到窗口。
> 本文只写**可执行的数字**；颜色以 `Scripts/Game/UI/UiKit.cs` 为准，改色只改那一个文件。

---

## 一、画布与像素栅格

| 项 | 值 | 依据 |
| --- | --- | --- |
| 设计分辨率 | 960×540 | 16:9，且能被 2 整除：内部渲染 2× 就是 1080p，正好 1:1 上屏 |
| 像素栅格 | 2 的整数倍 | 半像素在缩放后会出灰边 |
| 安全边距 | 左右 8、上下 6 | 画布本身无刘海，留边只为防描边贴边被裁 |
| 牌阵可用宽 | 788 | 960 − 两侧牌堆各 ~86 |

## 二、字号阶梯

中文楷体在小字号下笔画会粘连，所以下限卡在 10。

| 档 | 字号 | 行高 | 用途 |
| --- | --- | --- | --- |
| 大标题 | 24–26 | 1.15 | 结算标题、蓄势数字 |
| 标题 | 17 | 1.2 | 角色名 |
| 正文 | 15–16 | 1.25 | 卡名、按钮 |
| 数值 | 18 | 1.0 | 卡面效果行（红/黄/绿分段） |
| 辅助 | 11 | 1.1 | 状态行、牌堆标题、提示 |
| 微标 | 9–10 | 1.0 | 关键字角标、"蓄势"小标题 |

## 三、色板

底色（墨 / 宣纸 / 旧金 / 朱砂）与效果色（攻红、火橙、守黄、疗翠、毒深绿、冰青、雷紫、破绽紫、器物石青）见 `UiKit.cs`。

**新增三条约束**

1. 同一效果在卡面标签、边框、飘字、记录里必须是同一色，禁止另调一版。
2. 金属金分两档：`金·亮 0.84/0.69/0.38`（我方框）、`金·赤 0.78/0.56/0.36`（敌方框）。两档只差冷暖，不差明度 —— 明度差会让一边看着"更高级"。
3. 底色不用纯黑，最低到 `#0F0D0B`，纯黑在缩放后会出硬边。

## 四、点击区

| 元素 | 视觉尺寸 | 点击区 |
| --- | --- | --- |
| 交战记录开关 | 112×26 | 与视觉同大（鼠标端可接受 < 88） |
| 记录页签 | 70×22 | 同大 |
| 卡牌 | 132×160（随张数缩） | 整卡 |

触屏目标 ≥ 88×88 的原则只对移动端有效；本项目是鼠标端 960×540，按视觉尺寸给即可。

## 五、头像框（v3 · 老游戏质感）

尺寸受版面约束，不动：敌方 124×78，我方 124×86。

**v2 错在哪**：v2 是"抛光金属"——渐变框面、沿切线拉丝、内倒角亮圈、白色内亮线、宝石带高光。
技术上都对，但那是手游做法：满屏都在反光，看着"新"。v3 的判断标准是**能不能数清层数**——
老界面的边框之所以有厚度，是因为层与层之间是硬切换的 1~2 像素，不是靠渐变糊出来的。

**层序（由外向内，数值按框高的比例）**

| 层 | 区间 | 颜色（主色的倍数） |
| --- | --- | --- |
| 外投影 | 1px 硬边 | 黑 55%，不做柔光晕 |
| 外沿暗线 | 0.15 | ×0.30 |
| 外倒角 | 0.15–0.33 | 受光 ×1.12 / 背光 ×0.50 |
| 主框面 | 0.33–0.74 | 平色：受光 ×0.94 / 背光 ×0.76 |
| 内倒角 | 0.74–0.90 | 受光 ×1.04 / 背光 ×0.58 |
| 内沿暗线 | 0.90–1.00 | ×0.34 |
| 内圈暗缝 | 0.018 | ×0.38 —— **暗缝，不是亮线** |
| 画面 | — | 内阴影 + 底部渐隐（0.66 起） |

**受光判定**：距离场梯度当法线，`lit > 0.5` 即左上受光，只取两档，中间不插值。
**角饰**：四道切角各一颗方形铆片（往里收 0.050），面 ×1.05、座 ×0.28。
**宝石**：小、暗、无高光点（×0.42–0.78），只用来分辨敌我。
**切角**：0.22。
**落地**：`Resources/Shaders/portrait_frame.gdshader`。

## 六、卡面（v3 · 老游戏质感）

尺寸 132×160 基准，张数增多时按行宽反算，字号下限 0.62 倍。

**层序**：外 1px 暗线 → 1px 主色细线（受光 ×0.58 / 背光 ×0.30）→ 平色牌面（暗纸混主色 6%）→ 内 1px 主色细线（内缩 4.2px）→ 底部凹槽 + 进度条。
**圆角 2px**：老界面基本是直角，圆角一大就"现代"。
**一条线够了**：边框只留 1px 主色细线，不要 2px 亮框——那就是霓虹灯。
**空格位**：面色 ×0.78、内框改虚线 —— 压暗但别压成黑洞。
**图标**：裁圆 + 边缘柔化 + 外圈压暗 + **整体压暗到 0.74** —— 米色玉牌原画是卡面上最闪的一块（`icon_token.gdshader`）。
**进度条**：填充两档（×0.86 / ×0.60），槽沿压暗不压亮。
**落地**：`Resources/Shaders/card_frame.gdshader`，由 `CardView` 传 `accent / bar / rect / slot_empty`。

> ⚠ **颜色空间坑**：Godot 4 的 2D 是线性空间出图，着色器里写死的 `vec3(0.098)` 是**线性值**，
> 屏幕上会变成 0.33 的浅灰（整张卡发白）。底色一律用 `source_color` 的 uniform，不要写字面量。

## 七、血条与牌堆

| 元素 | 做法 |
| --- | --- |
| 血条 | 近黑凹槽（1px 暗金边 + 圆角 3）+ 填充（顶边 1px 亮线当高光）+ 数字 |
| 血量数字 | **不进条内**：11px 白字压在实心红条上会糊。放到名字那一行右端（名左、数右），条留干净 |
| 牌堆 | 三层错位纸（+6/+3/0）表示"一叠" + 最上层主色边框 + 内圈细线；数量 22px、标题 11px |

- 交战记录抽屉：仍是纯色块面板，未收进"木牌"体系。

## 九、放大算法：试过，已全部移除

**结论：这个项目不需要放大算法，只保留「画面精细度」。** 记录一下试过什么、为什么撤。

| 方案 | 实测 | 处理 |
| --- | --- | --- |
| EPX / Scale2x（曾叫 `edge_smooth.gdshader`） | 静态画面只改 0.38%~0.70% 的像素 | 已删 |
| xBR-lv3（`xbr_lv3.gdshader`，照 libretro 规则实现） | 改到 3.4%~8.5%，斜角确实更圆 | 已删 |
| 两级 xBR 到 4K 再缩回 1080p（`--chain=2`） | 58~59fps 跑得动，但最后那次缩小把文字糊了一层，整屏更软 | 已删 |

**为什么删**：这套 UI 是已抗锯齿的矢量/位图混合内容，不是像素画。放大算法在它身上只有两个结果 ——
几乎不动（EPX），或者把边缘磨圆（xBR），而"磨圆"与老游戏硬边质感相反。
真正决定清晰度的是**内部渲染倍率**，那已经是设置项了。

留一条经验：**xBR 家族只对"硬边、颜色少、整数倍"的像素画有效**；对照片、AA 文字、UI 只会变糊。
网上"某游戏用了 xBRZ 所以清晰"的说法大多来自二手转述（源头是一篇 2020 年的个人 Unity 实验，
原文写的是"效果像 xBR4x"，被洗成了"用了 xBR4x"）。

## 十、抗锯齿：三种锯齿，三套解法

**先分清锯齿的来源。** 这套 UI 的锯齿只有三类，混在一起讨论会得出错误结论（比如"加个 FXAA 就好了"）。

| 来源 | 长什么样 | 正确解法 | 为什么别的办法不行 |
| --- | --- | --- | --- |
| ① 着色器画的边（八角切角、斜面、宝石、凹槽） | 45° 边上的硬台阶 | **解析抗锯齿**：距离场 + `fwidth(d)` 给出半像素宽，所有边界改成 `smoothstep` | MSAA/FXAA 都是对**已画好的像素**做事，而这类边界是着色器里 `if` 切出来的，采样前就已经硬了 |
| ② 位图立绘 / 图标 | 边缘发毛、细节糊 | 提高内部渲染倍率（`RenderScale`）、或把显示尺寸做大 | 它们没有距离场，无法解析；只能靠更多像素或更好的采样 |
| ③ 文字 | 笔画发虚 | 字体自带栅格化 AA，够了 | 再叠 FXAA 只会把笔画糊掉（文字是最怕后期 AA 的东西） |

### 已落地的：解析抗锯齿（portrait_frame.gdshader v4）

```glsl
float d  = plate_d(p, half_w, c);      // 距离场：<0 在框内
float aa = max(fwidth(d), 1e-4);       // 一个像素有多宽（以距离场为单位）
float hw = aa * 0.5;

// 轮廓：不再 if (d > 0) 二分，改成按覆盖率混合
float cover = 1.0 - smoothstep(-hw, hw, d);

// 每一道倒角的边界同样处理，宽度 = 1 像素
colFrame = mix(colFrame, cBevel, smoothstep(0.15 - bw*0.5, 0.15 + bw*0.5, t));
```

代价为零（多几条 ALU），效果与分辨率无关。实测斜边从"硬切"变成 1 像素过渡（`12_抗锯齿开关.png` 左右对比）。
但注意：**框只有 34px 长的斜边，放大 8 倍仍能看出阶梯** —— 那是尺寸决定的，AA 变不出像素。

**开关**：设置 →「边缘抗锯齿」，写进 `SettingData.AntiAlias`，由着色器的 `aa_scale` uniform 控制
（关掉时取 1e-5 而不是 0 —— `smoothstep` 两端相等在 GLSL 里结果未定义）。
作用范围只有着色器画的那几条边：八角切角、宝石、四角铆片。卡面的圆角只有 2px、内框线是 1px，
抗锯齿在这两处不是变好而是变虚，所以不受这个开关影响；位图立绘与文字也不受影响。

### 照 Unity 那套搭一遍（已落地，含实测）

Unity 的 URP 一共四档（外加 Unity 6 的 STP），位置分两处：**管线层**（URP Asset 的 MSAA）
和**后处理层**（Camera → Rendering → Anti-aliasing 的 FXAA / SMAA / TAA）。本项目的对应关系：

| Unity | 做法 | 本项目 | 状态 |
| --- | --- | --- | --- |
| MSAA（URP Asset） | 对**几何边**多重采样 | `Viewport.msaa_2d` | 做了，实测无效（见下） |
| FXAA（Camera） | 全屏亮度边缘 + 方向混合，最省 | `post_aa.gdshader` mode 1 | 做了，可开 |
| SMAA（Camera） | 形态学边缘 + 图案匹配，比 FXAA 锐 | `post_aa.gdshader` mode 2（**简化版：无 area/search LUT**） | 做了，可开 |
| TAA（Camera） | 历史缓冲 + 运动矢量 | — | 不做：静态 UI 没有帧间变化，等于一张固定模糊 |
| STP（Unity 6 Upscaling Filter） | 时空上采样 | `RenderScale` 超采样 | 已有（更朴素） |
| —（Unity 没有对应项） | 着色器内解析 AA | `portrait_frame.gdshader` 的 `aa_scale` | 已有，默认开 |

**实测（静态画面，逐像素比对，1920×1080 内部渲染）**

| 档位 | 头像框改动像素 | 平均色差 | 文字锐度（拉普拉斯能量） |
| --- | --- | --- | --- |
| 关闭 | — | — | 6.0 |
| 解析 | 7.1% | 0.77 | **6.0（不受影响）** |
| 解析 + FXAA | 27.4% | 2.33 | **4.3（−28%）** |
| 解析 + SMAA | 12.8% | 1.15 | 6.1 |
| MSAA 4× | **0.00%（一个像素都没变）** | 0.00 | 6.0 |

**MSAA 为什么是 0**：它只对几何边采样。我们的框、卡、面板全是矩形 Quad，
八角切角是片元着色器算距离场切出来的、不是几何体的边，所以多重采样拿不到任何东西。
Unity 里有一模一样的坑：**Screen Space - Overlay 的 Canvas 不参与 MSAA**，因为 UI 直接画进后备缓冲、
绕过了摄像机的多重采样解析。结论是一样的 —— 边由 shader 画，MSAA 就管不着。

**FXAA 为什么伤文字**：它不区分内容，按亮度找边。11px 汉字笔画本身就是 1~2px 宽的亮度跳变，
被当成边一起磨，于是笔画糊、出现淡淡的光晕（`14_抗锯齿_文字对比.png` 第三行）。

**SMAA 为什么留**：边缘判定带彩度（逐通道取差），混合只取 2 个点并按亚像素覆盖率给权重，
所以文字锐度基本不掉（6.1 vs 6.0），斜切角的台阶也能抹平。代价是 1px 的内框线会软一档。
它在**像素模式（960×540 放大到 1080p）**下收益最明显 —— 那时台阶是 2px 宽，SMAA 能修掉（`15_像素模式SMAA.png`）。

### 设置里的四档（`SettingData.AaMode`）

| 显示 | `AntiAlias` | `PostAa` | 说明 |
| --- | --- | --- | --- |
| 关（硬边） | false | 0 | 2002 年观感，切角是台阶 |
| **解析（推荐）** | true | 0 | 只修着色器画的边，文字与位图一动不动 |
| 解析 + FXAA | true | 1 | 最软的一档，只在像素模式下值得试 |
| 解析 + SMAA | true | 2 | 想再平滑一点又不牺牲文字，选这个 |

MSAA 不进设置菜单（实测 0 收益），只在命令行留 `--aa=msaa` 供复验。

### 一句话结论

**能算出距离的边（着色器画的），别用屏幕空间 AA；算不出距离的（位图），才是 FXAA/SMAA 的活。**
Unity 里同一句话的版本是：MSAA 治几何边，FXAA/SMAA 治渲染结果，TAA 治时间采样；
**都不是"抗锯齿开关"，各自只治一类锯齿。**
