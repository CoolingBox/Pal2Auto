# 代码命名约定

> 来源：`D:\Godot\Projects\STS2Project`（杀戮尖塔 2，Godot + C#/.NET，3344 个 .cs，
> 玩法代码全在 `src/Core` 下 40 余个子目录）＋ 本项目 TinyFramework 的既有约束。
> 这份文档的作用是：**以后新增任何类型，先在这里查一格，查不到才允许命名。**

---

## 零、四条总则

1. **目录表达「这是什么」，后缀表达「怎么用」，前缀只表达「是不是抽象/空对象」。**
   判断一个类该叫什么，先问它属于哪一层，再看后缀表，最后才取业务名。
2. **一个概念只许一套叫法。** 已经有 `HandSlot`（手牌格）、`FighterState`（战斗方状态），
   新概念不许再叫 Slot / State 之外的名字，也不许把 Slot 挪作他用。
3. **中文进注释，英文进标识符。** 类型名不出现拼音，也不出现「DaXia」「Jianghu」这类音译。
4. **框架已给的不要重造。** 存档走 `SaveData` + `SaveManager`，配置走 `*Config` + `ConfigManager`，
   面板走 `BasePanel` + `UIManager`，单例走 `SingletonNode<T>`。见第五节。

## 一、STS2 实际在用的制度（统计）

| 后缀 | 数量 | 语义 | 典型例子 |
| --- | --- | --- | --- |
| `Type` | 44 | 枚举 | `RoomType`、`MapPointType`、`RewardType` |
| `Manager` | 31 | 有生命周期的单例服务 | `RunManager` |
| `Handler` | 30 | 针对某类对象的处理器（AutoSlay 自动测试） | `ShopRoomHandler` |
| `Extensions` | 27 | 枚举/类型上的扩展方法 | `RoomTypeExtensions` |
| `Model` | 27 | **内容定义**（策划数据，不可变） | `EncounterModel`、`ActModel` |
| `Set` | 26 | 一组同构对象的容器 | `RoomSet`、`RewardsSet`、`RunRngSet` |
| `State` | 25 | **运行态数据**（可变） | `RunState`、`MapPointState` |
| `Service` | 8 | 跨模块能力 | — |
| `Factory` | 4 | 复杂对象的构造 | — |
| `Collection` | 4 | 集合语义接口 | — |
| `Utility` | 3 | 无状态静态工具 | `ScoreUtility`、`DailyRunUtility` |

前缀：`I*` 58、`Mock*` 40、`Null*` 10、`Abstract*` 8。

**最值得抄的一条：`AbstractRoom` + `CombatRoom/EventRoom/MerchantRoom/RestSiteRoom/TreasureRoom`。**
基类只放共性（进/出、地图坐标、是否已完成），具体房间各自带自己的状态与迁移逻辑。
这是「停留点」类系统唯一不乱的写法。

## 二、目录 = 概念分类（STS2 的六大类，我们照搬语义、换词）

| STS2 目录 | 语义 | 我们的对应 | 说明 |
| --- | --- | --- | --- |
| `Runs/` | 一局的运行态与管理 | `RunState` / `RunManager` / `RunSave` | 一局 = Run，不叫 Session、不叫 Game |
| `Rooms/` | 一个「停留点」 | `DayPhase`（时辰） | 我们没有地图房间，有「一天里的几个时段」 |
| `Map/` | 路径与坐标 | `DaySchedule`（一天的时段表） | 我们的「地图」是日程，不是节点图 |
| `Rewards/` | 战斗后产出 | `Reward` + 子类 + `RewardSet` | 银两/卡/器物/附魔各一个子类 |
| `Models/` | 内容定义（策划数据） | `*Config`（框架 `ConfigManager`） | 我们已经是这个体系，不改 |
| `Entities/` | 运行期实例 | `*State` 或无后缀业务类 | 实例不叫 Model |
| `Events/` | 选项 | `EventOption` / `EventConfig` | — |

## 三、后缀语义表（新增类型对照这张表选）

| 后缀 | 什么时候用 | 什么时候**不要**用 |
| --- | --- | --- |
| `*Config` | 一行策划数据，来自 `Resources/Config/*.json` | 带运行时状态的东西 |
| `*State` | 运行期可变数据，一局结束就丢 | 需要落盘的（那要 `*Save`） |
| `*Save` | 继承 `SaveData`，由 `SaveManager` 落盘 | 内存态临时数据 |
| `*Manager` | 有生命周期、需要 Init/Tick 的服务 | 纯函数工具（用 `*Utility`） |
| `*Service` | 跨模块能力，无状态或有缓存 | 单场战斗逻辑（那是内核） |
| `*Panel` | `BasePanel` 子类，一屏 UI | 屏内的小控件（`*View`） |
| `*View` | 可复用的 UI 控件（卡、牌堆、头像框） | 一屏面板 |
| `*Set` | 一组同构对象，有增删查 | 有顺序语义的（用 `*Queue`/`*List` 字段） |
| `*Type` | 枚举 | 常量表（用 `static readonly` 数组） |
| `*Extensions` | 枚举/类型的扩展方法 | 业务逻辑 |
| `*Option(s)` | 参数对象（构造参数超 4 个时） | 普通 DTO |
| `*Utility` | 无状态静态方法 | 需要注入依赖的 |
| `*Kernel` | 纯逻辑、不碰渲染/资源的算法内核 | — |

## 五、与框架的边界（别重造）

| 需求 | 用框架现成的 | 不要自己做 |
| --- | --- | --- |
| 落盘/读盘 | `SaveData` 子类 + `SaveManager.Save/ Load` | 自己写 FileAccess + JSON |
| 配置表 | `*Config : BaseConfig` + `ConfigManager` | 自己读 json |
| 面板 | `BasePanel` + `UIManager.ShowPanel<T>()` | 自己 new Control 挂根节点 |
| 单例 | `SingletonNode<T>` | 自建静态 Instance |
| 音效 | `AudioManager.PlayUISFX` | 直接 AudioStreamPlayer |
| 字体/配色/按钮 | `UiKit` | 每次手写 StyleBox |

**唯一允许自建的是「框架管不到的那层」**：一局的运行逻辑（`RunState`/`RunManager`）
和它与存档的映射（`Capture()` / `Apply()`，由 `SaveManager` 落盘）。

## 六、禁忌清单（每条都踩过）

1. **`*Info` 与 `*Data` 不许并存。** 本项目 `*Data` 已经归「存档数据」（`SaveData` 子类），
   `*Info` 一律不用 —— 语义重叠的命名会让接手的人每次都要翻定义。
2. **不许用 `*Helper`。** 静态工具叫 `*Utility`，扩展方法叫 `*Extensions`。
3. **UI 层不许放战斗规则。** `*Panel` 只做「读 state → 摆控件」；判定在 `DeckBattle` / `RunManager`。
4. **不许把 `DeckProgress`（跨局永久进度）和「本局牌组」混成一个字段。**
   前者是解锁/永久移除，后者是 `RunState.Deck`，两者生命周期不同。
5. **布尔命名**：字段 `_isXxx`，属性 `IsXxx`，别用 `xxxFlag`。
6. **枚举值用 PascalCase 全称**（`PhaseType.Encounter`），不用缩写（`PhaseType.ENC`）。
